# 调试与恢复

在包根目录打开 PowerShell。SSH 使用准备阶段在本机生成的 `work/debug_key`。

## OHOS SSH

```powershell
.\tools\openssh\ssh.exe -i .\work\debug_key -p 2222 root@172.30.55.1
```

常用命令：

```sh
param get bootevent.boot.completed
pidof render_service
df -h /data
ip address show wlan0
tail -30 /data/local/tmp/nabu-motion.log
tail -30 /data/local/tmp/nabu-hardware-load.log
```

## 独立 RAM 恢复 SSH

```powershell
.\tools\openssh\ssh.exe -i .\work\debug_key -p 2223 -o UserKnownHostsFile=NUL -o StrictHostKeyChecking=no root@172.30.55.1
```

该环境位于 RAM，可在 OHOS 用户态故障时继续访问。它的主机密钥每次启动重新生成。进入真正 OHOS 根目录：

```sh
chroot /proc/1/root /system/bin/sh
```

要在下次启动只保留恢复环境，可从原生 OHOS 创建：

```sh
touch /mnt/nabu-state/ohos/hold-native
```

恢复自动进入 OHOS：

```sh
rm /mnt/nabu-state/ohos/hold-native
```

`OHOS recovery` 菜单项通过内核参数直接停在恢复环境，不启动 OHOS 用户态。

## HDC

HDC 从自己安装的 DevEco SDK 使用，本包不提供 SDK 工具：

```powershell
$hdc = "$env:ProgramFiles\Huawei\DevEco Studio\sdk\default\openharmony\toolchains\hdc.exe"
& $hdc tconn 172.30.55.1:8710
& $hdc -t 172.30.55.1:8710 shell 'hidumper -s RenderService -a gles'
& $hdc -t 172.30.55.1:8710 shell 'hidumper -s MultimodalInput -a -l'
& $hdc -t 172.30.55.1:8710 shell 'hidumper -s DisplayManagerService -a -a'
```

连接 Wi-Fi 后也能使用平板实际的 Wi-Fi 地址和同样的端口。

## USB 网络

USB gadget 提供 RNDIS 和 ACM 串口。Windows 的该 RNDIS 接口应开启 DHCP，不需要设置网关。调试路由优先级 9000 保证 Wi-Fi 连接后 USB 的回包仍走 USB。

遇到 SSH 断开，先区分三个状态：

1. 2222 不通，2223 可用：进入 RAM 恢复环境检查 OHOS。
2. RNDIS 或串口存在：检查 Windows 网络地址和串口，不需要立即刷写。
3. RNDIS、串口、Wi-Fi 都不存在：可能停在内核早期初始化。当前内核仍有热重启失败，需要长按电源重新启动；进入菜单后选择 OHOS。

## 返回 fastboot 或恢复 Android

能进入系统时：

```sh
/debug/nabu-reboot bootloader
```

也可以关机后按住音量下连接 USB。进入 fastboot 后：

```powershell
.\recovery.ps1
```

恢复完整 Android 使用自己型号对应的官方 fastboot ROM。单独恢复 boot 备份不能还原已经替换的 super 和 userdata。
